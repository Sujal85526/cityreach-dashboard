### `apps/web/.env.production.local`

Values come from Firebase console → Project settings → General → _Digital Manager Web_ → SDK setup and configuration → Config.
They identify the project and are not secrets (access is controlled by `firestore.rules`), but the file stays out of git so each machine can point at its own project.

```
VITE_USE_EMULATORS=false
VITE_FIREBASE_PROJECT_ID=digital-manager-f916d
VITE_FIREBASE_API_KEY=<apiKey>
VITE_FIREBASE_AUTH_DOMAIN=digital-manager-f916d.firebaseapp.com
VITE_FIREBASE_APP_ID=<appId>
```

## Deploy

```bash
# 1. Rules or indexes changed? Deploy them first, the website may depend on them.
npx firebase login
npx firebase deploy --project prod --only firestore    # rules + indexes (works on Spark)
pnpm indexes:wait                                      # until every index is READY

# 2. Website: push to main. Vercel builds and deploys it (about a minute).
git push origin main
```

Pushing to `main` **is** a production deploy, so push only when the change is ready to go live. Manual deploy without a push: `vercel deploy --prod`.
New indexes take a few minutes to build; pages that need them show "The query requires an index… currently building" until then.

## Handover to the student

1. Firebase console → Project settings → Users and permissions → add the student's Google account as **Owner**.
2. After they accept, remove the developer account. (Spark plan: no billing to move.)
3. GitHub → repo Settings → Danger zone → **Transfer ownership** to the student.
4. The student creates their own `apps/web/.env.production.local` (values above) and runs `npx firebase login`.
5. Vercel → project `digital-manager` → Settings → **Transfer project** to the client's Vercel account, then reconnect the GitHub repo after its transfer (Settings → Git).
6. The domain `managr.me` stays in the client's Tasjeel.ae account; renew it yearly (next due 2027-10-27).

## First manager account (one-time, production)

The app has no public sign-up (managers create staff), so the very first manager is created by hand:

1. Firebase console → Authentication → Users → **Add user** (email + password). Copy the **User UID**.
2. Firestore → Data → **Start collection** `users` → Document ID = that UID, with five string fields:
   `branchId` = `main`, `role` = `manager`, `status` = `active`, `name`, `email`.
3. Sign in to the app. The rest of the profile is filled in automatically, and the
   **"Set up your coffee shop"** screen appears once (creates `branches/main` with default settings).
4. Optional, for demos: **Settings → Sample data → Load sample data** (8 staff without logins, shifts,
   two weeks of history, stock, tasks). **Remove sample data** deletes exactly those records later.
5. Add the real team from **Employees → Add employee**.
