# Data model

Collections (see `packages/shared/src/constants/collections.ts`; schemas in
`packages/shared/src/schemas`). Every document carries `createdAt` / `updatedAt`, and most carry
`branchId`.

| Area       | Collections                                                                          |
| ---------- | ------------------------------------------------------------------------------------ |
| Business   | `branches`, `users`, `shifts`                                                         |
| Attendance | `attendance` (id `{uid}_{date}`), `attendancePhotos`, `rota`, `swapRequests`          |
| People     | `leaveRequests`, `payslips`, `candidates`, `training`, `goals`, `performance`         |
| Operations | `tasks`, `checklistTemplates`, `checklistRuns`, `handovers`, `incidents`, `feedback`  |
| Food/kit   | `temperatureLogs`, `inspections`, `equipment`, `maintenance`                          |
| Stock      | `inventoryItems`, `stockMovements`, `suppliers`, `purchaseOrders`                     |
| Finance    | `salesDays`, `expenses`                                                               |
| Files      | `documents`, `documentChunks` (compressed bytes in pieces)                            |
| System     | `notifications`, `activity` (audit log), `reports`                                    |

Conventions: dates are local `YYYY-MM-DD` keys in the branch time zone; instants are timestamps;
natural keys use deterministic ids so writes are idempotent; display fields that lists need are
copied onto the document (assignee name, supplier name) and updated in the same batch.
# Data model (Cloud Firestore)

Top-level collections, each document scoped by `branchId`. Timestamps are Firestore `Timestamp` (UTC); local shift times are `"HH:mm"` strings interpreted in the branch `timeZone`. Every document has `createdAt` and `updatedAt`. Enums are lowercase strings (`on_time`, `in_progress`), defined in `@cityreach/shared`.

## Required composite indexes (`firestore.indexes.json`)

The emulator doesn't enforce indexes, so a missing one only shows up on the real project. Every multi-filter, `in`, or unsorted-range query needs an entry; the file is the source of truth (63 indexes as of 2026-10-21).

- `attendance`: `branchId ASC, dateKey ASC` ✅ (attendance page range); `branchId ASC, employeeId ASC, dateKey DESC` ✅ (profile history); `employeeId ASC, dateKey DESC` ✅ (employee's own history)
- `attendancePhotos`: `branchId ASC, takenAt ASC` ✅ (daily 90-day cleanup)
- `documents`: `branchId ASC, createdAt DESC` ✅ (documents page); `branchId ASC, expiresOn ASC` ✅ (expiry reminders)
- `payslips`: `employeeId ASC, month DESC` ✅ (employee's own); `branchId ASC, month ASC` ✅ (month table)
- `leaveRequests`: `branchId ASC, createdAt DESC` ✅ (manager page); `employeeId ASC, createdAt DESC` ✅ (employee's own); `branchId ASC, employeeId ASC, createdAt DESC` ✅ (profile)
- `tasks`: `branchId ASC, deadline ASC` ✅ (report periods); `branchId ASC, status ASC, deadline ASC` ✅ (overdue check); `branchId ASC, status ASC, completedAt DESC` ✅ (board: recently completed); `assigneeId ASC, deadline DESC` ✅ (my tasks)
- `inventoryItems`: none needed yet (the page loads the branch's items with one equality query)
- `stockMovements`: `branchId ASC, itemId ASC, createdAt DESC` ✅ (stock history); `branchId ASC, createdAt DESC` ✅ (CSV export)
- `notifications`: `branchId ASC, recipientId ASC, createdAt DESC` ✅ (manager list); `recipientId ASC, createdAt DESC` ✅ (employee list)
- `activity`: `branchId ASC, createdAt DESC` ✅ (recent activity, last-hour count)
- Every record collection (`expenses` … `goals`, `checklistTemplates`, `swapRequests`): `branchId ASC, createdAt DESC` ✅ (lists)
- `expenses`, `salesDays`: `branchId ASC, date ASC` ✅ (month totals); `purchaseOrders`: `branchId ASC, status ASC, createdAt DESC` ✅
- `rota`: `branchId ASC, date ASC` ✅ (week grid, absences); `employeeId ASC, date ASC` ✅ (my rota); `branchId ASC, employeeId ASC, date ASC` ✅
- `checklistRuns`: `branchId ASC, date ASC` ✅ (today's runs)
- `training`, `goals`: `branchId ASC, employeeId ASC, createdAt DESC` ✅ (profile tab, my growth); `training`: `branchId ASC, expiresOn ASC` ✅ (certificate reminders)

## Roles

Schemas: `packages/shared/src/schemas/*` (zod, instants as `Date`; the web converts Timestamps in `lib/firestore.ts`).

Role, branch and status are stored on `users/{uid}` only (no custom claims: they need server code, and the project runs on the free Spark plan). The web app reads that document at sign-in; `firestore.rules` reads it with one cached `get()` per request. `status: inactive` blocks every request. Security rules: `firestore.rules`.
